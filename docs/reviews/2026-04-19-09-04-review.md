## Critical Issues

1. **[Correctness] `$dsgo_filter_taxonomy` is `unset()` inside the slug-translation cleanup then reused downstream.** `src/blocks/query-filter/render.php:470–495` — any checkbox/select filter block with `showCounts: true` silently drops to `false` as soon as any cross-filter is active in the URL. Fix: rename the loop-local to `$dsgo_iter_taxonomy` and drop it from the `unset()`.
2. **[API Design] `designsetgo/query` `save()` changed from `null` → `<div {...innerBlocksProps} />` without a deprecation.** `src/blocks/query/save.js` — existing v2.1 `designsetgo/query` blocks will hit "This block contains unexpected or invalid content" with an "Attempt Recovery" prompt. Fix: add `src/blocks/query/deprecated.js` with `{ isEligible, save: () => null, migrate: passthrough }`.
3. **[A11y] Filter `<label>` elements are not associated with their controls.** `src/blocks/query-filter/render.php:44, 86, 162` — floating `<label>` with no `for`/`id`. SR users hear the `<select>`/`<input>` with no accessible name. WCAG 1.3.1 / 4.1.2. Fix: generate stable `id` from `$param_name` and wire `for`.
4. **[A11y] Active filter chips only announce "Remove filter", not the filter dimension.** `src/blocks/query-filter/render.php:335–343` — ambiguous when multiple filter dimensions are active. WCAG 2.4.6. Fix: SR text of the form `Remove %1$s: %2$s`.
5. **[Testing] Zero tests for `FilterIndexCLI`, including the destructive `drop` subcommand.** `includes/blocks/class-query-filter-index-cli.php` — 166 lines untested. `drop` clears three options + drops the table and is irreversible; a regression that fails to delete `designsetgo_db_version` silently prevents auto-reinstall.
6. **[Testing] Zero JS unit tests for any IAPI store action or `initInfiniteObserver`.** `src/blocks/query/view.js` — `loadMore`, `setFilter`, `setFilterDebounced`, `toggleFilter`, `removeActiveFilter`, `resetAll`, the observer callback, and the reduced-motion branch are all uncovered.

## Important Issues

### Security
- **Unsanitised REST `params` written to `$_GET`.** `includes/blocks/class-query.php:518–521` — downstream sanitises, but any third-party hook reading `$_GET` during nested block renders sees raw arrays.
- **`designsetgo_query_registered_filters` hook values aren't re-sanitised.** `includes/blocks/class-query-filter-registry.php:88–89` — third-party `source` values flow into `wp_get_post_terms`/`get_post_meta` without `sanitize_key`. Not currently exploitable but a trust-boundary gap.
- **Wrong docstring on `check_filter_register_permission`.** `includes/blocks/class-query.php:377–383` — claims it guards `/query/preview` but that route actually uses `check_edit_posts_permission`. Misleading; could cause a future reviewer to loosen the wrong guard.

### Performance
- **`FilterRegistry::all()` re-queries + re-filters on every call.** Called once per tracked meta key per save — CPU amplification proportional to meta-key count per request. Fix: static per-request cache; bust on `register`/`unregister`.
- **`do_rebuild_all` / `do_rebuild_filter` use `OFFSET` pagination.** `includes/blocks/class-query-filter-index-rebuilder.php` — quadratic scan time on large `wp_posts`. Fix: keyset pagination using `WHERE ID > $last_id`.
- **`count_for_options()` is uncached.** `includes/blocks/class-query-filter-index.php:2771` — every filter interaction refreshes all filter blocks, and every filter block issues one self-join per render. Wrap in `wp_cache_get` / `wp_cache_set` keyed on `filter_key + active_filters hash`.
- **`IntersectionObserver` teardown not wired to filter-refresh innerHTML swap.** `src/blocks/query/view.js:356–441` — observer outlives its detached sentinel; multiple swaps accumulate observers. Track observer on the sentinel (or in a module `WeakMap`) and disconnect on re-initialisation.
- **`usePosts` re-fetches on every attribute change.** `src/blocks/query/components/EditorPreviewList.js:5663–5667` — `JSON.stringify(attributes)` dep means color/spacing/etc edits trigger preview refetch. Fix: depend only on query-relevant attribute subset.

### Correctness
- **No cleanup of observer on filter-refresh swap.** Same surface as the perf finding but framed as correctness — after the innerHTML swap the old observer can fire `button.click()` against a disconnected DOM node, with `ctx.page` bound to the old scope.
- **`setFilterDebounced` closes over `ctx` captured at call time.** `src/blocks/query/view.js:237–259` — after a concurrent `setFilter` completes during the 250 ms window, the debounced callback runs against stale `ctx.busy`, letting two refreshes overlap. Fix: `getContext()` inside the timeout.
- **Rebuild lock acquire is not atomic in the stale-lock path.** `includes/blocks/class-query-filter-index-rebuilder.php:49–51` — two concurrent clicks both see `is_locked()=false`; both call `update_option`; both run `TRUNCATE`. Fix: MySQL `GET_LOCK()` or `INSERT IGNORE` + short TTL.
- **`register_hooks()` idempotency guard checks only `save_post`.** `includes/blocks/class-query-filter-index-hooks.php:29–38` — external partial removals cause the other four hooks to duplicate-register. Fix: single static `$registered` flag.
- **`sanitize_text_field()` on `REQUEST_URI` in `handle_render`.** `includes/blocks/class-query.php:514–515` — mangles `+`, encoded chars. The restored superglobal is corrupted for any shutdown handler. Fix: store raw, with a phpcs-ignore comment explaining why.

### Testing
- **No single-page boundary case for infinite scroll render.** `tests/phpunit/blocks/query/pagination-infinite-render-test.php` — every test seeds `totalPages=2`; the explicit single-page guard has no regression test.
- **`walk_blocks_for_filters` meta-kind branch has no test.** `includes/blocks/class-query-filter-index-hooks.php:92–111` and the matching filter-index test — only `taxonomy` filters are auto-registered on save. Meta-kind filter blocks silently never register, and there's no test either asserting they do or documenting that they don't.
- **No render-route test for `/query/render`.** The route used on every filter interaction has no happy-path or schema assertion.
- **`edit.test.js` mocks are tautological.** Commit `831c1675` — `useEntityRecords` returns `{ records: [], hasResolved: true }` unconditionally, so the template-editable `idx === 0` path and every `BlockPreview` branch is never exercised.
- **`filter-counts-test.php` mutates `$_GET` at class level.** `tests/phpunit/blocks/query/filter-counts-test.php:37` — a mid-test failure leaves superglobal state in place for subsequent tests.
- **`preview-route-test.php` missing invalid-taxonomy / unknown-source paths.**

### API Design
- **REST `config` arg on `/query/filter-register` has no nested schema.** `includes/blocks/class-query.php:89–92` — runtime code validates, but the declared schema is just `type: object`. Auto-docs + schema consumers can't see the shape.
- **Plan doc `docs/plans/2026-04-19-dynamic-query-v2.2-facets.md` still uses `facet` throughout.** Now a permanent reference in the repo; developers reading it will find class names and hook names that don't match shipped code.

### Accessibility
- **Reset control is `<a>`, not semantic button.** `src/blocks/query-filter/render.php:392–397` — add `role="button"` to preserve the no-JS href fallback while fixing AT semantics.
- **Count `<span>` rendered inside `<option>` for select variation.** `src/blocks/query-filter/render.php:147–156` — browsers strip HTML from `<option>`; the count feature is silently inconsistent across browsers for the select kind. Fix: append count as plain text, no `<span>`.
- **No terse result-count announcement for search/filter refreshes.** Container `aria-live="polite"` announces every item's full text instead of "N results found". WCAG 4.1.3. Fix: dedicated `role="status"` sibling region with `aria-atomic="true"`.
- **Search `<input>` has no accessible name when `label` is blank.** `src/blocks/query-filter/render.php:43–52` — `placeholder` is not a label. Fix: fallback `aria-label` when `$label` is empty.

## Detailed Analysis

### Security
Two important gaps, both defense-in-depth rather than directly exploitable: raw REST `params` copied to `$_GET` before being downstream-sanitised; and the `designsetgo_query_registered_filters` hook surface allowing third-party code to supply unsanitised `source` values. Strong practices overall: consistent `$wpdb->prepare()` usage with placeholder arrays for the `count_for_options` intersection subqueries; layered REST permissions (read / `edit_posts` / `manage_options`); both nonce and cap verified on every mutation; `JSON_HEX_APOS` used for `wp_json_encode` in single-quoted HTML attribute contexts.

### Performance
Schema design is good (`filter_key_value` composite index, `object_lookup` index, DELETE-then-bulk-INSERT idempotency). The two highest-impact regressions under realistic load are the `OFFSET`-pagination rebuild cliff and the uncached `count_for_options()` on every filter interaction — both defeat the purpose of the index once you pass a few thousand posts or a few filter blocks per page. The `FilterRegistry::all()` call amplification compounds both paths.

### Correctness & Logic
One critical live-site bug (`$dsgo_filter_taxonomy` `unset()` corrupts counts under cross-filter state), three important async/concurrency issues (observer teardown, debounced `ctx` capture, lock race), and two data-integrity concerns around hook registration idempotency and URI sanitisation. The filter-index data layer (DELETE-then-INSERT, `object_type` scoping on every DELETE, slug→ID translation with `ctype_digit` guard) is well-designed.

### Testing
Core data-layer classes (`FilterIndex`, `FilterIndexRebuilder`, `FilterRegistry`) are thoroughly covered at integration level. Gaps cluster at the edges: WP-CLI has zero coverage including the destructive `drop`; IAPI store actions have zero JS coverage; `edit.test.js` mocks bypass the rendering logic under test; render route has no PHPUnit coverage. The edit.test.js mocks from `831c1675` are the most surprising — they render the test tautological for the preview path.

### API Design
The facet → filter rename is complete and consistent in shipped code. The only genuine breaking change is `designsetgo/query`'s `save()` moving from `null` → `<div …/>`, which requires a deprecation entry per the plugin's own CLAUDE.md rules. Both `designsetgo/query-filter` and `designsetgo/query-pagination` still `save() { return null; }` so their new attributes (`showCounts`, `paginationKind`, `autoPauseAfter`, etc.) are purely additive and don't need deprecations.

### Accessibility
Checkbox/numbered-pagination/load-more button surfaces are semantic and correct. The new filter variations (search, sort, select) ship floating `<label>`s with no programmatic association — a blanket SC 1.3.1 / 4.1.2 failure that affects every site using them. Active filter chips name the action ("Remove filter") but not the dimension, failing SC 2.4.6. The search debounce path has no terse result-count live region (SC 4.1.3). `prefers-reduced-motion` handling is correct and the load-more button degrades cleanly.
