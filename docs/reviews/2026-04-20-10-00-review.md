## Critical Issues

### [Security] SQL in public `designsetgo_query_did_render` action payload
`src/blocks/query/render-posts.php:144` — The full `$wpdb->last_query` (including table structure and all WHERE clauses) is captured in the `$capture` array and fired via `do_action('designsetgo_query_did_render', $capture)` on every public page request containing a Query block. Any third-party plugin hooked to this action on the frontend receives raw SQL. Gate the `sql` field behind `defined('QM_VERSION')` or an admin capability check.

### [Security] Missing `esc_attr()` on style binding CSS values
`includes/class-style-binding.php:85` — `$value` is concatenated into the inline style string without `esc_attr()`. The blocklist (`url(`, `expression(`, `javascript:`) does not cover `{`, `}`, `data:`, or CSS hex-escaped variants. `esc_attr()` should be applied to `$value`, and the blocklist should be extended.

### [Testing] `DateQueryBuilder` mode-driven rendering is entirely uncovered
`tests/unit/blocks/query/date-query-builder.test.js` — Only 2 of ~8 testable behaviors are covered (initial render + add clause). The conditional rendering of `after`/`before` inputs per `mode`, relation selector visibility with multiple clauses, `updateClause`, `removeClause`, and `onDeselect` are all completely absent. A regression in the `showAfter`/`showBefore` conditional would pass all current tests.

### [API] `taxQuery` schema change has no block deprecation
`src/blocks/query/block.json` + `src/blocks/query/index.js` — `include_children` is a new field on leaf clauses, and leaf/group discrimination is a new shape union. Per CLAUDE.md: "Required when changing: attribute schema." A deprecation with `isEligible` that migrates legacy clauses (injecting `include_children: true`) must be added.

### [Accessibility] "Remove" button in `MetaQueryBuilder` has no per-clause accessible name
`src/blocks/query/components/MetaQueryBuilder.js:83–90` — Button has no `aria-label`. With multiple clauses, a screen reader user hears "Remove, Remove, Remove" with no context. Use `aria-label={ sprintf(__('Remove meta filter for "%s"', 'designsetgo'), clause.key || ...) }`.

### [Accessibility] `ClauseGroupShell` action buttons are ambiguous at nested depth
`src/blocks/query/components/ClauseGroupShell.js:84–93` — `"+ Clause"`, `"+ Group"`, and `"Remove group"` repeat identically at every nesting level. Screen reader users cannot differentiate which group's buttons they are on. Scope labels using the `depth` prop: e.g., `aria-label="Add clause to nested group level 2"`.

### [Accessibility] Style-binding "Remove" button lacks per-entry accessible name
`src/extensions/style-binding/filters.js:95–103` — Same ambiguous "Remove" pattern. Use `aria-label={ sprintf(__('Remove style binding for "%s"', 'designsetgo'), prop) }`.

## Important Issues

### Security

- **[Security/Minor] Inconsistent sanitizer for meta key args** — `post-meta` source uses `sanitize_text_field()` while `metabox` uses `sanitize_key()`. Standardize on `sanitize_text_field()` for all meta keys (legitimate keys can contain uppercase). `includes/class-style-binding.php:116,154`
- **[Security/Minor] `Date.now()` used as CSS custom property key** — Two simultaneous editor sessions could collide. Use `crypto.randomUUID()` or `clientId`-based seeding instead. `src/extensions/style-binding/filters.js:1639`

### Performance

- **[Perf/Important] QM collector stores unbounded `wp_args`** — Every query render appends the full WP_Query args array (which may contain large `post__in` arrays from relationship sources) to `$this->renders` with no cap. On pages with nested relationship loops (e.g., 10 outer posts × N inner queries), memory grows O(N × args_size). Add a 50-render cap and truncate `post__in`/`post__not_in` arrays >20 items. `includes/class-query-qm-collector.php:52`

- **[Perf/Important] `$wpdb->last_query` shows wrong SQL (COUNT, not posts SELECT)** — After `new WP_Query($args)`, `$wpdb->last_query` is the `FOUND_ROWS()` or COUNT query, not the posts SELECT. Use `$query->request` instead — it holds the exact SQL WP_Query ran for the posts fetch. `src/blocks/query/render-posts.php:144`

- **[Perf/Minor] Recursive PHP builders have no depth guard** — Neither `designsetgo_build_tax_query_entry()` nor `designsetgo_build_meta_query_entry()` cap recursion depth. A maliciously crafted template import payload could cause a stack overflow. Add a `$depth` parameter with a guard at depth 10. `src/blocks/query/render-posts.php:20–95`

- **[Perf/Minor] `TermPicker` executes N `useSelect` calls for N clauses** — Each `TermPicker` renders its own `getEntityRecords({ per_page: -1 })` subscription. Though the core data store caches the HTTP response, N selector subscriptions are created per inspector open. Hoist to the parent `TaxQueryBuilder`. `src/blocks/query/components/TaxQueryBuilder.js:31`

- **[Perf/Minor] `renderClause` is an unstable reference in `MetaQueryBuilder`/`TaxQueryBuilder`** — Defined as an inline `const` inside the component body, recreated every render, breaking `React.memo` memoization on nested `ClauseGroupShell` instances. Wrap in `useCallback`. `src/blocks/query/components/MetaQueryBuilder.js:44`

- **[Perf/Minor] `key={i}` / `key={idx}` on mutable clause lists** — Index-based keys cause React to reuse the wrong DOM node when a middle clause is removed. Use stable IDs seeded at clause creation. `src/blocks/query/components/DateQueryBuilder.js:110`, `ClauseGroupShell.js:69`

### Correctness

- **[Correctness/Important] `str_contains`/`str_ends_with` fatal on PHP 7.4** — These are PHP 8.0+ functions. The plugin targets PHP 7.4+ and `StyleBinding` is always instantiated. Any block render on PHP 7.4 calls `apply_style_bindings()` → fatal error. Replace with `strpos()` equivalents. `includes/class-style-binding.php:81,98`

- **[Correctness/Important] `$wpdb->last_query` shows COUNT query** — Same as performance finding above; functional correctness impact in QM SQL column. `src/blocks/query/render-posts.php:144`

- **[Correctness/Important] `wp_json_encode()` return value not checked** — Returns `false` on encoding failure (non-UTF-8 meta values, resource types injected via filters). Silent empty `<pre>` with no error indication. Check for `false` before passing to `esc_html()`. `includes/class-query-qm-output.php:78`

- **[Correctness/Important] Single-child nested group triggers `_doing_it_wrong()` in WP 6.1+** — `count($sub) > 1` (where `$sub` starts with `['relation' => 'AND']`) correctly guards against zero children but allows exactly one child, producing `['relation'=>'AND', 0=>[...]]`. WP_Query requires ≥2 sub-clauses when `relation` is present. Unwrap single-child groups as a bare leaf instead. `src/blocks/query/render-posts.php:33`

- **[Correctness/Important] `metabox` source arg-key mismatch — silent broken feature** — Editor serializes `args.key` (falls through to default in `argKey` logic), but PHP reads `$args['id']`. Every metabox-sourced style binding silently resolves to `null`. Fix `argKey` in JS to map `designsetgo/metabox` → `'id'`. `src/extensions/style-binding/filters.js:116` + `includes/class-style-binding.php:138`

- **[Correctness/Minor] CSS property regex rejects digits in standard property names** — `^[a-z][a-z\-]*$` blocks any standard property containing a digit and all vendor-prefixed properties (starting with `-`). Extend to `^-?[a-z][a-z0-9\-]*$`. `includes/class-style-binding.php:45`

- **[Correctness/Minor] `DateQueryBuilder` doesn't normalize absent `clauses` key** — `attributes.dateQuery` could be `{}` (e.g., from a malformed import), causing `dateQuery.clauses` to be `undefined` and `[...undefined]` to throw. Use `attributes.dateQuery?.clauses ?? []`. `src/blocks/query/components/DateQueryBuilder.js:47`

### Testing

- **[Testing/Important] Empty-group pruning in recursive builders is untested** — `count($sub) > 1` guard in both tax and meta builders is never exercised. - **[Testing/Important] `StyleBinding` `expression()` and semicolon injection guards untested separately** — Only one dangerous-value test exists, covering a compound payload. The `expression(` and `;` branches each need isolated tests. `tests/phpunit/extensions/style-binding-test.php`

- **[Testing/Important] `StyleBinding` parent-stack (`current_post_id()`) has no test** — The `$GLOBALS['designsetgo_parent_stack']` path is never exercised. A key rename would silently resolve bindings against the wrong post in nested loops. `includes/class-style-binding.php:172–181`

- **[Testing/Important] `withStyleBindingInspector` HOC has zero JS tests** — The arg-key derivation logic, `addEntry`, `updateEntry`, `removeEntry`, and the entire inspector panel render path are uncovered. `src/extensions/style-binding/filters.js:43–133`

### API Design

- **[API/Important] `designsetgo_build_date_query()` is missing as a named function** — Tax and meta query builders are named public PHP functions; date query building is inlined. Third-party code hooking `designsetgo_query_args` cannot reuse the validation/mode translation logic. Extract into `designsetgo_build_date_query( array $date_query_attr ): array`. `src/blocks/query/render-posts.php`

- **[API/Important] `StyleBinding::resolve()` bypasses v2.4 security gates** — The class re-implements all five source cases from scratch, bypassing the post-password/viewable/protected-meta gates from `designsetgo_register_bindings_source()`. Values from password-protected posts can leak through style bindings. Delegate resolution to `apply_filters('designsetgo_style_binding_resolve', null, $source, $args)` using registered callbacks, removing the built-in switch. `includes/class-style-binding.php:102–160`

- **[API/Important] Editor UI uses `PanelBody` instead of `DsgoInspectorPanel`** — CLAUDE.md (Theme 3): "never reach for `PanelBody` directly." `PanelBody` is deprecated in WP 6.7+. Replace with `DsgoInspectorPanel`. `src/extensions/style-binding/filters.js:81`

- **[API/Important] `renderClause` passes `(idx, patch)` — double-index footgun** — `ClauseGroupShell` passes `idx` to `renderClause`, which must then pass `idx` back to `updateEntry`. Pre-bind: call `renderClause(entry, (patch) => updateEntry(idx, patch), () => removeEntry(idx))` instead. `src/blocks/query/components/ClauseGroupShell.js:26–30,79`

- **[API/Minor] `designsetgo_query_did_render` not fired from `render-users.php` / `render-terms.php`** — QM panel will show 0 renders for user/term queries, which is confusing for debugging. Fire the action from all three render paths with matching `$capture` shape.

- **[API/Minor] `mode` field on `dateQuery` clauses is redundant with `after`/`before` presence** — PHP builder infers from `mode` but the information is already implicit in which fields are non-empty. Two sources of truth: bugs arise if `mode === 'after'` but a stale `before` value remains. Server should infer from field emptiness; `mode` can remain a UI-only hint.

- **[API/Minor] Temp CSS custom property key persists in serialized content** — `--dsgo-binding-1745264000000` keys accumulate in post content if authors abandon bindings. Use `prop: ''` as sentinel and validate client-side, or use `crypto.randomUUID()`.

- **[API/Minor] `isAddDisabled` blocks `+ Group` even when adding groups doesn't require taxonomies** — Disabling both `+ Clause` and `+ Group` when no taxonomies exist is too aggressive; groups themselves are valid with no taxonomy. Separate into `isClauseDisabled` and `isGroupDisabled`. `src/blocks/query/components/ClauseGroupShell.js:87`

## Detailed Analysis

### Security

**Verdict: Needs Fixes**

The diff shows generally strong security hygiene: allowlist-based query building (not blocklists), proper `defined('ABSPATH')` guards, `esc_html()` throughout QM output, `WP_HTML_Tag_Processor` for safe style injection. Two issues require fixing:

1. **SQL in public action payload** — `designsetgo_query_did_render` fires on frontend pages and exposes `$wpdb->last_query` to any hooked callback. Gate with `defined('QM_VERSION')`.
2. **Missing `esc_attr()` on CSS values** — The style binding value is not escaped before concatenation. Extend blocklist to include `{`, `}`, `data:` and apply `esc_attr()`.

**Strengths:** Input allowlisting throughout PHP builders; `sanitize_key()`/`absint()` for taxonomy names/term IDs; QM integration correctly gated behind `defined('QM_VERSION')`; `WP_HTML_Tag_Processor` used instead of naive regex replacement; `BLOCKED` set prevents style-binding on `core/freeform` and `core/missing`.

---

### Performance

**Verdict: Needs Fixes**

1. **Use `$query->request`** instead of `$wpdb->last_query` — the current code captures the COUNT query, not the posts SELECT.
2. **Cap QM collector memory** — Add a 50-render cap and truncate large `post__in`/`post__not_in` arrays in `wp_args` before storage.
3. **Add depth guard to recursive PHP builders** — Protect against deep nesting in template imports.

Remaining items (N `useSelect` calls, `renderClause` instability, index keys) are editor-only concerns and can be addressed as follow-up.

**Strengths:** `empty()` fast-path on `StyleBinding::apply_style_bindings`; QM correctly deferred behind `defined('QM_VERSION')`; recursive PHP builders are well-structured and eliminate flat-only loop duplication.

---

### Correctness & Logic

**Verdict: Needs Fixes**

Two issues require immediate attention:

1. **`str_contains`/`str_ends_with` on PHP 7.4** — Fatal error on every block render on PHP 7.4 hosts. Replace with `strpos()`.
2. **`metabox` arg-key mismatch** — Editor writes `args.key`, PHP reads `args.id`. All metabox style bindings silently broken.
3. **Single-child nested group** — Triggers `_doing_it_wrong()` in WP 6.1+. Unwrap to bare leaf.

**Strengths:** Sanitization is thorough throughout PHP builders; dangerous CSS value rejection covers major injection vectors; QM files are guarded three ways; `WP_HTML_Tag_Processor` used correctly.

### Testing

**Verdict: Gaps Found**

The PHP side of `DateQueryBuilder` (`before` mode) and QM collector behavioral logic are untested. The JS `DateQueryBuilder` covers only initial render + addClause (2 of 8 behaviors). `ClauseGroupShell` — the recursive heart of both builders — has no dedicated tests. `withStyleBindingInspector` HOC and `StyleBinding` parent-stack resolution are entirely absent. Two security guards in `StyleBinding` (`expression(` and semicolon) are only partially covered.

**Strengths:** Tax query builder additions are well-structured with behavioral integration tests; `render-posts-test.php` tests assert the WP_Query output array shape (the right level); `style-binding-test.php` correctly uses `remove_all_filters` cleanup; tax test mock invokes actual selector logic via `select()` callback rather than hard-mocking.

---

### API Design

**Verdict: Needs Fixes**

Two issues require pre-merge fixes:

1. **`metabox` arg-key mismatch** — Silently breaks all metabox style bindings (see Correctness section).
2. **`StyleBinding::resolve()` bypasses v2.4 security gates** — Password-protected post values can leak through style bindings, inconsistent with block bindings behavior.

The missing `designsetgo_build_date_query()` function and `renderClause` index double-passing are important API design issues to fix before this becomes a stable extension point.

**Strengths:** Additive-only `block.json` changes (no save() output change); `if (!function_exists())` guards on new PHP helpers; `designsetgo_style_binding_resolve` filter contract is consistent with existing filter patterns; `BLOCKED` set shows good extension awareness.

---

### Accessibility

**Verdict: Needs Fixes**

Three critical accessible name issues must be fixed: ambiguous "Remove" buttons in `MetaQueryBuilder`, `ClauseGroupShell`, and `style-binding/filters.js`. The code has a solid foundation — all interactive elements use correct semantic elements, all form controls have visible labels — but the recursive UI creates duplicate accessible names that screen reader users cannot differentiate.

Two important issues: no `speak()` announcements for dynamic mutations (users have no confirmation feedback), and index-based `key` props causing focus loss on deletion.

**Strengths:** All controls use proper semantic HTML elements; all form controls have visible `label` props; destructive "Remove date clause" and "Remove taxonomy filter" buttons carry `aria-label` (partial coverage); `ToggleControl` used for boolean flags; `__next40pxDefaultSize` applied consistently; `@wordpress/i18n` used throughout.
